# Cascade в SG-Gateway 23.05

**Подробная инструкция для версии 23.05 (публичное тестирование)**

## Что такое Cascade и зачем он нужен

Cascade позволяет последовательно соединить **два сервера SG-Gateway**:

```text
Телефон / ПК → Gateway A → выбранный межсерверный протокол → Gateway B → Интернет
```

В обычной схеме один сервер принимает соединение клиента и сам выпускает трафик в интернет. В Cascade эти задачи разделены:

- **Gateway A — сервер клиентов:** принимает соединения устройств и решает, какой трафик отправить через Cascade.
- **Gateway B — выходной сервер:** принимает межсерверное соединение и выпускает соответствующий трафик в интернет.

Например, устройство подключается к Gateway A в Германии по VLESS Reality. Gateway A соединяется с Gateway B во Франции через NaiveProxy. Если правило Routing направляет запрос в Cascade, внешний сайт видит **выходной IP Gateway B**, а не Gateway A.

Это полезно для выбора выходной страны/IP, разделения входного и выходного серверов, независимого выбора клиентского и межсерверного протоколов, а также настройки отдельных правил маршрутизации.

**Ограничения:** дополнительный сервер может увеличить задержку; Cascade не обещает анонимность или увеличение скорости. При недоступности маршрута Cascade автоматического перехода на прямой выход нет.

## Что потребуется

1. Два установленных и работающих SG-Gateway 23.05.
2. Сетевая доступность Gateway B с Gateway A.
3. Рабочий выход в интернет на Gateway B.
4. Настроенные протоколы в **Connections** на Gateway B.
5. Для TLS-зависимых транспортов — работающие HTTPS и сертификат на Gateway B.
6. Открытые нужные TCP/UDP-порты. В типовой конфигурации SG-Gateway публичный вход использует порт **443**.

**Начинайте с Gateway B.**

## Шаг 1. Подготовьте Gateway B

1. Откройте раздел **Cascade** на втором сервере.
2. Выберите роль **Gateway B · выходной сервер**.
3. В **Connections** проверьте настройку нужных протоколов. Для дополнительных TLS-транспортов предварительно настройте HTTPS.
4. Вернитесь в **Cascade** и нажмите **«Создать / скачать config»**.
5. Сохраните JSON-файл на своём компьютере.

Панель подготовит служебный доступ для Gateway A и сформирует конфигурацию с доступными каналами. **Config содержит данные доступа:** не публикуйте JSON на форумах и не прикладывайте его к отчётам об ошибках.

На Gateway B не нужно выбирать приоритет четырёх каналов — этим управляет Gateway A.

## Шаг 2. Импортируйте config на Gateway A

1. Откройте **Cascade** на первом сервере.
2. Выберите роль **Gateway A · сервер клиентов**.
3. Нажмите **«Выбрать config»** и укажите файл, полученный от Gateway B.
4. Нажмите **«Применить config»**.
5. Дождитесь появления сетки каналов и сведений о Gateway B.

**Импорт не означает успешное соединение.** На этом этапе параметры сохранены, но доступность транспорта ещё нужно проверить.

## Шаг 3. Выберите четыре канала

В интерфейсе показаны **10 позиций**:

| Профиль | Особенность |
| --- | --- |
| Reality TCP | Xray / Reality |
| XHTTP Reality | Xray / XHTTP с Reality |
| AmneziaWG 3.1 | Транспорт AWG |
| Mieru | Транспорт Mieru |
| XHTTP TLS | Требует HTTPS |
| Hysteria 2 | Требует соответствующей серверной настройки |
| AnyTLS | Требует HTTPS |
| TUIC | Требует HTTPS |
| NaiveProxy | Требует HTTPS |
| SG-Net | **Резерв**, не действующий межсерверный канал |

На Gateway A **первые четыре позиции слева — выбранные каналы**. Перетаскивайте профили, чтобы выбрать четвёрку и установить порядок приоритета, затем нажмите **«Сохранить»**.

Пример порядка: NaiveProxy → Reality TCP → AnyTLS → Hysteria 2. Это **пример**, а не рекомендуемая настройка для любой сети.

Четыре канала **не объединяются для увеличения скорости**: активным может быть один транспорт. В режиме приоритета система выбирает первый готовый канал из заданной четвёрки. Возможность выбора резервного транспорта не гарантирует бесшовного переключения любого существующего соединения.

## Шаг 4. Проверьте каналы и включите Cascade

1. На Gateway A нажмите **«Проверить все каналы»**.
2. Посмотрите результаты для каждого выбранного профиля.
3. Убедитесь, что как минимум один канал помечен **«ГОТОВ»**, а необходимое семейство IP (IPv4 или IPv6) прошло проверку.
4. Нажмите **«Включить каскад»**.

Обозначения:

- **ГОТОВ** — канал прошёл проверку.
- **АКТИВЕН** — канал выбран текущим маршрутом.
- **ВЫБРАН** — канал входит в четвёрку, но необязательно готов.
- **НЕТ CONFIG** — отсутствуют параметры транспорта.
- **НУЖЕН TLS** — требуются настройки HTTPS/сертификата.
- **НЕ ГОТОВ / ERROR** — проверка соединения не прошла.
- **РЕЗЕРВ** — позиция пока не является рабочим транспортом.

Проверка относится к конкретному моменту времени. **«ГОТОВ» не гарантирует постоянную доступность.**

## Шаг 5. Настройте Routing — это обязательная часть

**Включить Cascade недостаточно, чтобы весь клиентский трафик пошёл через Gateway B.** На Gateway A откройте раздел **Routing** и выберите нужную схему:

- **«Ресурсы, заблокированные в РФ через Каскад · IPv4»** — для соответствующей категории ресурсов.
- **«Весь интернет через Каскад · IPv4»** — для трафика, охватываемого этим правилом.
- **Пользовательские правила** — используйте выходы **«Каскад · IPv4»** или **«Каскад · IPv6»** для отдельных категорий трафика.

Нажмите **«Применить»** в Routing.

IPv4 и IPv6 проверяются и выбираются **раздельно**. Принудительного fallback с IPv4 на IPv6, с IPv6 на IPv4 или с Cascade на Direct для такого правила нет. Если выбранный маршрут недоступен, соответствующее соединение может прекратиться.

## Шаг 6. Проверьте реальный маршрут с клиентского устройства

1. Подключите телефон/ПК **к Gateway A**, используя обычный клиентский профиль.
2. Сначала используйте обычный выход через Gateway A и посмотрите внешний IPv4 в сервисе проверки IP.
3. Затем на Gateway A выберите в **Routing** схему **«Весь интернет через Каскад · IPv4»** и примените её.
4. Обновите IP-проверку **на том же клиентском устройстве**.
5. В работающем Cascade должен отображаться **IP Gateway B** для соответствующего маршрута.

Важно: статус «АКТИВЕН» в панели показывает выбор канала, но **не заменяет фактическую проверку IP**. Если IP остался прежним, сначала проверьте Routing, семейство IP и используемый устройством профиль.

## Что видно на Gateway B

Gateway B получает от A сведения о:

- имени и адресе Gateway A;
- четырёх выбранных каналах и их порядке;
- текущем активном транспорте;
- готовности и времени последней связи.

**Gateway B отображает, но не выбирает каналы за Gateway A.** Если информация на B устарела, возможно нарушение синхронизации статуса; это само по себе не доказывает, что пользовательский трафик не проходит.

## Как добавить дополнительные каналы после настройки HTTPS

Если сначала использовались только базовые каналы, после подготовки HTTPS:

1. Настройте сертификат и нужные транспорты в **Connections** на Gateway B.
2. На Gateway A в разделе **Cascade** нажмите **«Обновить B»**.
3. Выберите четыре доступных транспорта и сохраните порядок.
4. Повторите **«Проверить все каналы»**.

Если обновление не удалось, повторно скачайте JSON на B и импортируйте его на A. **Удалять рабочий Cascade только ради обновления каналов не требуется.**

## Устранение типичных проблем

**Нет готового канала.** Проверьте доступность B, конфигурацию протокола в Connections, HTTPS/сертификат и результаты «Проверить все каналы».

**НЕТ CONFIG / НУЖЕН TLS.** Подготовьте отсутствующий протокол или сертификат на B, затем обновите каналы на A.

**Канал готов, но внешний IP не поменялся.** Проверьте, действительно ли трафик направлен в Cascade через **Routing**; отдельно проверьте IPv4/IPv6.

**Gateway B не показывает актуальный активный транспорт.** Проверьте доступность управляющей связи между серверами и время последнего обновления.

**После включения нет интернета.** Верните на A прямой маршрут в **Routing** для восстановления доступа и отдельно проверьте выбранный канал Cascade. Для правил Cascade автоматический переход на Direct не предусмотрен.

**Нужно сменить роль A/B.** Сначала удалите существующую конфигурацию Cascade. Кнопка **«Изменить роль»** предупреждает об удалении текущих настроек.

## Отключение и удаление

- **«Отключить каскад»** — выключает Cascade, сохраняя конфигурацию.
- **«Удалить каскад»** — удаляет настройки Cascade на Gateway A; обычные клиентские профили не должны удаляться.
- **«Изменить роль»** — требует удаления конфигурации перед переключением A ↔ B.

## Статус функции

Cascade — одна из основных новых возможностей **23.05**, но версия предназначена для публичного тестирования. Особенно полезны сообщения о фактическом IP Gateway B, работе выбранных транспортов, синхронизации A/B и поведении при потере связи.
